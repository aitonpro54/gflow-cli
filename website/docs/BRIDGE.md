# Extension bridge 0.1: локальная очередь для официального расширения

`gflow-bridge` координирует действия агента через уже установленное официальное
расширение Chrome. Bridge не открывает браузер, не нажимает кнопки, не читает
авторизацию и не обращается к Flow. Стандартные `gflow auth`, `gflow mcp`, `gflow serve`
и upstream worker — отдельные поверхности; их не следует использовать как запасной
маршрут этого workflow.

## Конфигурация процесса

| Переменная | Значение |
|---|---|
| `GFLOW_BRIDGE_STATE_DB` | Обязательный абсолютный путь к одному локальному SQLite-файлу для всех CLI/MCP процессов |
| `GFLOW_BRIDGE_EXPECTED_PROFILE` | Обязательное точное имя согласованного Chrome-профиля, задаётся приватно |
| `GFLOW_BRIDGE_COOLDOWN_MIN` | Минимальная пауза, по умолчанию 25 секунд |
| `GFLOW_BRIDGE_COOLDOWN_MAX` | Максимальная пауза, по умолчанию 70 секунд |

Допустимо `25 <= MIN <= MAX <= 3600`. Для более осторожного режима диапазон можно
увеличить. Нулевая пауза и нижний предел менее 25 секунд запрещены. Bridge читает
только environment процесса; `.env` автоматически не загружается. Пример с фиктивными
значениями для PowerShell:

```powershell
$env:GFLOW_BRIDGE_STATE_DB = Join-Path $env:LOCALAPPDATA 'gflow-bridge/state.sqlite'
$env:GFLOW_BRIDGE_EXPECTED_PROFILE = 'Configured Chrome Profile'
python -m gflow_cli.bridge status
python -m gflow_cli.bridge --help
```

После установки пакета доступен эквивалентный entrypoint `gflow-bridge`. Все процессы
должны получать один и тот же путь и профиль. Не создавайте другую БД и не меняйте
конфигурацию, чтобы обойти остановку или паузу. Профиль закрепляется в БД своим SHA-256;
другой ожидаемый профиль отклоняется. Путь не является CLI/MCP параметром. Держите БД
вне репозитория, защищайте её средствами ОС и не редактируйте вручную. Bridge не
является границей безопасности от другого локального процесса с доступом к файлу.

UNC, device paths, сетевые диски Windows, symlink/junction/reparse ancestors запрещены
до открытия файлов. Используйте обычный локальный каталог на локальном диске. Это не
защита от враждебной одновременной подмены каталогов или сетевого mount в ОС.

## Операции и порядок действий

Все обычные команды возвращают один JSON-объект. `--help` выводит справку.
Перед каждым submit агент должен заново наблюдать нужный профиль и состояние Flow
через официальное расширение. Сравнение имени — проверка заявления контроллера;
bridge не может криптографически доказать, какой профиль открыт.

| CLI | MCP tool | Назначение |
|---|---|---|
| `enqueue --kind --request-key --request-fingerprint` | `bridge_enqueue` | `image`, `video` или `upscale`; безопасный идентификатор и SHA-256 параметров |
| `status [--job-id]` | `bridge_status` | Задание или общий halt, cooldown и active |
| `list [--limit]` | `bridge_list` | Общая FIFO очередь, 1–1000 записей |
| `claim --observed-profile --controller-id` | `bridge_claim` | Захватить первое pending задание; получить секретный `claim_token` один раз |
| `prepare-submit --job-id --claim-token --observed-profile` | `bridge_prepare_submit` | Durable checkpoint перед одним submit |
| `record-started --job-id --claim-token --media-id` | `bridge_record_started` | Необязательно: записать наблюдаемый media ID |
| `finish --job-id --claim-token --artifact-path --sha256` | `bridge_finish` | Проверить локальный артефакт и начать обязательную паузу |
| `unknown --job-id --claim-token` | `bridge_unknown` | Неизвестный исход после возможной отправки; остановить очередь |
| `halt --signal` | `bridge_halt` | Остановить при `flow_403`, `flow_429`, `captcha`, `unusual_activity` |

MCP использует те же имена параметров с `_` вместо `-`. Результаты отказов MCP имеют
форму `{"problem": { ... }}`; успешность JSON-RPC сама по себе не разрешает действие.
CLI выводит Problem Details напрямую и завершает процесс ненулевым кодом: 11 для
ошибок входных данных/конфигурации, 16 для отказа состояния/хранилища. Envelope содержит
`type`, `title`, `status`, `detail`, `instance`, `remediation_hint`, `retryable=false`.
`cooldown` дополнительно возвращает `retry_after`; bridge не спит и не повторяет вызов.

В БД нет prompt, browser token, cookies, HAR, signed URL или ответов Flow. Не передавайте
их в идентификаторы, имена файлов, причины оператора и логи. `request_key`, `controller_id`
и `media_id` принимают до 128 ASCII символов: буквы, цифры, `_`, `.`, `:`, `-`.
Fingerprint — 64 строчных hex символа SHA-256. Его рассчитывает вызывающий код по всем
существенным параметрам запроса. Повтор enqueue того же ключа с теми же kind/fingerprint
возвращает текущее задание; изменение параметров — `idempotency_conflict`. Полный payload
остаётся у контроллера. Claim token — случайный локальный секрет владения, не авторизация
Google; сохраняйте его приватно до завершения, не публикуйте и не логируйте.

`BEGIN IMMEDIATE` защищает общий FIFO для generation и upscale. Одновременно возможно
одно active задание во всех процессах. TTL и автоматического перехвата нет. Потеря токена
или падение процесса требует ручного разбора. Вызовы claim/prepare запрещены при halt и
cooldown. Состояние `submit_attempted` фиксируется **до** возврата `action_permitted=true`.
Агент использует это разрешение ровно один раз через официальное расширение; сам bridge
не расходует permit и не контролирует клик. Повтор prepare всегда отклоняется. При потере
ответа после commit новый permit не выдаётся, даже если клик фактически не состоялся.

После возможного submit запрещено повторять генерацию из-за timeout, ошибки скачивания
или неизвестного результата. Сохраните `unknown`, проверьте Flow вручную. Unknown
удерживает halt после перезапуска. Пока запись остаётся `submit_attempted`/`started`,
новые claim тоже заблокированы. При CAPTCHA, unusual activity и Flow 403/429 сообщайте halt
независимо от HTTP-статуса: отказ внутри HTTP 200 тоже означает остановку. Поздний finish
может записать реальный файл, но никогда не снимает halt.

Первый успешный finish хеширует файл вне SQL-lock, проверяет базовую структуру и затем
условно фиксирует completed. `video` принимает MP4; `image` — PNG/JPEG/WebP/GIF; `upscale`
принимает любой из них. MP4 проверяется по границам boxes и наличию ftyp/moov/mdat;
PNG — по структуре chunks, CRC и IEND; JPEG/GIF — по сигнатуре и конечному маркеру;
WebP — по RIFF-сигнатуре, типу и объявленному размеру. Это **не** полная проверка codec,
декодируемости, качества изображения или соответствия содержимого запросу. HTML и
очевидная недописанная структура отклоняются. SHA-256 должен совпасть с фактическим
файлом; изменение размера/mtime во время проверки отклоняется. Файл должен быть закрыт
и стабилен, защищён от параллельной записи. Повтор finish с тем же путём/hash возвращает
прежнюю квитанцию без повторной проверки файла; другие параметры — `finish_conflict`.

Пауза выбирается случайно один раз **после завершения**, сохраняется в БД и переживает
перезапуск. Длительная генерация не поглощает её. Повтор finish не пересчитывает паузу.

## MCP stdio

Запускайте отдельную registry через `gflow-bridge mcp` или
`python -m gflow_cli.bridge mcp` с теми же environment variables. Доступны ровно девять
`bridge_*` tools из таблицы. HTTP/SSE transport, upstream tools, автоматическое исполнение
и операторский reset отсутствуют. Обычные операции CLI/MCP используют один BridgeService.

## Ручное восстановление, только CLI

После проверки фактического результата оператор может закрыть active задание:

```text
gflow-bridge reconcile --job-id 1 --reason "Результат проверен вручную" --acknowledge
gflow-bridge resume --reason "Причина остановки устранена" --acknowledge
```

`reconcile` переводит запись в `abandoned`, никогда в pending. Если submit мог состояться,
добавляется консервативная пауза MAX от момента разбора. Для завершения найденным
артефактом сначала используйте finish с прежним claim token. `resume` требует отсутствия
active заданий, снимает только halt и сохраняет cooldown; причина и явное подтверждение
обязательны (3–256 символов, без URL и управляющих символов). Эти две команды намеренно
не имеют MCP twin: восстановление требует отдельного операторского решения и проверки
возможной отправки. Не создавайте новое задание как автоматический повтор неизвестного.

## Проверки и предел результата

Офлайн-тесты покрывают реальные CLI subprocess и MCP stdio, конкурирующие процессы,
commit fault, crash/replay, halt/cooldown после рестарта, артефакты и изоляцию импортов.
Они подтверждают только локальный координатор. Реальные submit и генерация Flow в этом этапе не запускались;
для проверки generation требуется отдельное поручение.
