# Predict: мост через официальное расширение Chrome

## Verdict: CAUTION

Пять независимых проверок дали CAUTION, 8/10 каждая: архитектура, безопасность, производительность, CLI/MCP UX и минимальность. Предел двух одновременных помощников соблюдался; проверки выполнены волнами. Стандартный `FlowApiClient` получил STOP для данного пользовательского маршрута, поскольку извлекает cookies и запускает собственный браузер.

## Findings

- Архитектура: отдельный entrypoint `gflow-bridge` и пакет `bridge/`. Не подменять Playwright Page объектом CUA. ADR 13 upstream не меняется; CDP transport не добавляется.
- Безопасность: durable запись `submit_attempted` обязана завершиться до выдачи одноразового разрешения UI-действия. Replay не выдаёт разрешение снова. Unknown блокирует очередь. Нельзя использовать callback upstream worker, который продолжает работу после неудачной записи checkpoint.
- Производительность: короткие SQLite-транзакции; ожидание браузера и хеширование файла вне SQL-lock. Cooldown возвращает время следующей попытки без блокирующего ожидания. Долгая генерация не поглощает паузу после завершения.
- CLI/MCP: один сервис и одинаковые операции; отдельная MCP registry. Параметры пути БД, профиля и транспорта не предоставляются в MCP tools. Ошибки остановки имеют `retryable=false`.
- Минимальность: собственная небольшая очередь оправдана тем, что обычный `FlowWorker` автоматически исполняет `generation_queue` через запрещённый здесь lifecycle; upstream codec также не поддерживает upscale. Общие таблицы создали бы риск автоматического исполнения.

## Обязательные условия

1. Bridge только координирует; Chrome управляет агент через установленное официальное расширение. Browser/runtime/auth imports отсутствуют.
2. Один отдельный фиксированный локальный файл БД. Один active job для image/video generation и upscale. Межпроцессный захват транзакционный.
3. Идемпотентность enqueue; один permit перед submit; подтверждение отправки и завершения никогда не создаёт новый permit.
4. Unknown и halt сохраняются при перезапуске. Не отбирать active job по TTL. Разбор неизвестного исхода выполняется отдельно, без автоматической повторной отправки.
5. Обязательная случайная пауза 25–70 секунд по умолчанию; допускается увеличить диапазон, но не отключить/уменьшить нижний предел 25 секунд. Выбранная пауза сохраняется один раз.
6. CAPTCHA, unusual activity, Flow 403/429 останавливают выдачу заданий, включая отказ внутри HTTP 200. Поздний успех не снимает halt.
7. Не сохранять cookies, токены, HAR, подписанные URL и произвольные ответы сервера. Имя профиля настраивается приватно, без персональных значений в опубликованном коде.
8. Файловая проверка подтверждает локальный артефакт, а не визуальное качество или успешность Flow. Не выдавать офлайн-симуляции за live proof.
